## 1. Security, second pass (8 minutes)

> **Say:** "Since last time I did a second security pass. It covers how long
> people stay signed in, what a stolen session can do, and what leaves the app.
> - A browser left alone is signed out after an hour, with a warning, and
>   everyone signs in again after 12 hours. Before, a sign-in lasted six months.
> - If someone copies a sign-in key and uses it, the session ends, and the
>   Activity Log records it.
> - Authenticator codes work once. New logins choose their own password, and
>   weak passwords are refused.
> - The firm can require the second step for every login.
> - When you take someone's role away, it takes effect at once, not 15 minutes
>   later.
> - A vendor name can no longer run code in a print page or a CSV export.
>
> It's all live, with tests."

- [ ] **1. A new login chooses its own password.** In the private window, sign
  in as the test login. Only "Finish setting up your login" opens. Try
  `Password2026!`: it is refused.
- [ ] **2. Taking a role away works at once.** Make the test login a firm admin,
  then change it to Staff. In the private window, open Setup → Users: "Only a
  firm admin can do this."
- [ ] **3. Require the second step.** Setup → Users → Sign-in security → tick
  "Require the second step for every login". At its next sign-in, the test
  login has to set it up first. Untick it afterwards unless the firm decides to
  keep it.

## 2. Is the app secure now? (4 minutes)

> **Say:** "No system is ever fully secure, and we shouldn't promise that to
> clients. What I can say is that the code has had two full security reviews,
> everything they found is fixed, and one client can never reach another
> client's records. What's left is how we run it: four things before
> November 1."

Before November 1:

1. **Take the first production backup and prove it restores.** There is no
   backup of production yet.
2. **Copy `FIELD_ENCRYPTION_KEY` and the sign-in secrets into a password

   IDs.
3. **Require the second step for every login** (step 3).
4. **Get uploaded files off Railway's disk.** Today they are in no backup.
   They move to Supabase Storage with the move to Azure and Supabase (Part 5).

Before outside customers come on in January:

- replace the `xlsx` spreadsheet reader;
- set up a standby database;
- have someone outside test the app's security.
