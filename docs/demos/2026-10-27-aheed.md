## Moving to Azure and Supabase (3 minutes)

> **Say:** "We talked about moving to Azure and Supabase. It's about three to
> four days of work plus a test pass. It's much easier before November 1, while
> there's no real client data to move."

What we use now, and where each part would go:

| Part | Now | After the switch |
|---|---|---|
| Database (Postgres) | Railway | Supabase |
| API server (also runs the Gmail inbox and recurring entries on timers) | Railway | Azure App Service |
| Web app | Netlify | Azure Static Web Apps, or stay on Netlify |
| Uploaded files | Railway disk, in no backup | Supabase Storage |
| AI reading, Gmail, sign-in | Anthropic, Google, our own code | Unchanged |

What it would take:

1. **Database, half a day.**
   - Copy the data across with our backup tool, then change the API's
     `DATABASE_URL`. Supabase is plain Postgres and has the three extensions we
     use.
   - We keep our own sign-in and don't use Supabase's.
   - Turn Supabase's Data API off, since we don't use it. Otherwise tables
     without row-level security can be reached with its public key.
2. **API on Azure, one to two days.**
   - Build it with a Dockerfile, since Azure doesn't use Railway's build.
   - Start it with the migrations first, as now, with the `/health` check.
   - Keep "Always On" set and run one copy. Otherwise the timer jobs stop, or
     run twice.
   - Put the secrets in App Settings, and deploy from GitHub Actions.
3. **Files, a few hours.** Supabase Storage works with the code we already
   have for S3-style storage; only settings change. Azure Blob Storage would
   need a small new piece of code.
4. **Web app, half a day if it moves.** Move the security headers from
   `netlify.toml` into Azure's config file, and change the API address.
5. **Switch-over, one evening.**
   - Take a last copy of the data and restore it.
   - Point the web and phone apps at the new API. The phone app needs a new
     build.
   - Everyone signs in again.

Why switch:

- **Backups:** Supabase's Pro plan keeps daily backups, which Railway's Hobby
  plan doesn't.
- **Reliability:** it gets us off the host that went down on 10-22.
- **Fit:** Azure fits a firm that already works in Microsoft (Teams).
